# MDA-8051 Virtual Laboratory

A local React/TypeScript application with an editable CodeMirror 6 assembly IDE, a byte-executing MCS-51 CPU, debugging tools, and a provisional MDA trainer board. No account, API key, or online compilation is required.

**The two laboratory PDFs were not attached.** The supplied project brief was available. Experiments 01 and 02 are implemented from that brief; exact PCB placement, J6 wiring, LED order beyond the stated LED 5 result, PPI registers, and monitor sequences remain unverified. See [hardware status](docs/HARDWARE.md). Unimplemented devices are visibly labeled and accessing their reserved addresses raises a diagnostic.

## Run on Windows 11

1. Install **Node.js 24** from [nodejs.org](https://nodejs.org/). Node 24.20.0 was used for verification.
2. Extract the project ZIP to a folder you can write to, if using the archive.
3. Double-click **Start-Lab.cmd**. It serves the included production build at **http://127.0.0.1:8051/** and opens your default browser.
4. Keep the launcher terminal open. Press **Ctrl+C** in that terminal to stop the server.

The included `dist/` build and built-in Node HTTP server need no npm dependencies or Internet connection to run. If `dist/` is missing, the launcher installs dependencies and builds it; that first dependency installation requires Internet access.

If port 8051 is occupied, use PowerShell from this project folder:

```powershell
$env:PORT = '8052'
node scripts/serve.mjs --open
```

To edit, test, and rebuild the application:

```powershell
npm.cmd ci
npm.cmd run dev
# Open the URL printed by Vite, normally http://127.0.0.1:5173/

npm.cmd test
npm.cmd run build
node scripts/serve.mjs
```

Using `npm.cmd` avoids PowerShell script-execution-policy errors; no policy change is necessary. Local browser storage is specific to the URL/port. Export Project before moving between the development and production URLs.

## First program

Click **New**, replace its contents with this source, and click **Assemble**:

```assembly
ORG 0000H
MOV A,#00H
MOV R0,#05H
LOOP:
    INC A
    DJNZ R0,LOOP
STOP:
    SJMP STOP
END
```

Run and Pause: A should be 05H, R0 should be 00H, and PC should remain at 0007H. Change `#05H` to `#09H`, assemble again, and the result becomes 09H. The CPU executes the generated bytes, never the source text or example name.

- **F9** assembles; **F5** runs/pauses; **F7** steps; **Ctrl+S** downloads source.
- The white-and-blue desktop workspace fits the window; the green trainer board scales automatically. Use **Text − / +** for 90–150% text zoom, **Layout** to adjust column widths, editor height and execution desk height, and **Fit window** to restore defaults. View preferences are saved locally. Long source, listings and inspector content scroll within their panels.
- CodeMirror supplies syntax colors, line numbers, indentation, undo/redo, find/replace (Ctrl+F), selection and copy/paste. Label blocks can be folded.
- Click the breakpoint gutter or a listing row to set a breakpoint. Run stops before that instruction. Run again resumes past that stop; a looping program can hit it again. Use Step for exact inspection.
- Step Source Line executes until the source line changes, with a 1,000-instruction guard for self-loops. It falls back to one instruction when source mappings are unavailable.
- **Stop** pauses and moves PC to the loaded entry while preserving registers. **Reset** clears CPU RAM/registers and restarts at entry; the selected monitor initialization sets SP=50H. **Hardware reset** uses PC=0000H and SP=07H.
- Editing or switching source pauses and resets execution and requires successful assembly before Run, Step or GO. These controls never assemble implicitly. Imported machine code can execute directly without source-level mapping.
- Double-click a register to edit it. Click a memory byte to edit it. Values entered in these controls are hexadecimal.
- The instruction panel records before/after registers, changed RAM/SFR/XDATA, port pins, flags, instruction bytes and machine cycles. History retains the last 200 instructions and shows the latest 30 for selection.
- Watch expressions accept registers, `IRAM:30`, `SFR:90`, `CODE:2000`, and `XDATA:2000`. Bare hex addresses refer to IRAM. Device peeks do not acknowledge keyboard flags.
- All source tabs are autosaved to local browser storage. **Save** and **Save as** download actual source files. Use **Open** to reopen them. Save As changes the tab's filename. Project JSON preserves sources, breakpoints, wiring, monitor options, and the loaded CODE image; it is not a complete CPU checkpoint.

## Instructions and assembly language

The assembler and decoder cover **all 255 defined standard Intel 8051 opcode bytes**, including every register, indirect, direct, immediate, relative, bit and complemented-bit form. A5H is reserved and raises a CPU exception.

Implemented mnemonics:

| Family | Instructions |
|---|---|
| Transfer | MOV, MOVC, MOVX, PUSH, POP, XCH, XCHD |
| Arithmetic | ADD, ADDC, SUBB, INC, DEC, MUL AB, DIV AB, DA A |
| Logic | ANL, ORL, XRL, CLR, CPL, SWAP |
| Rotate | RL, RLC, RR, RRC |
| Boolean | SETB; bit/C forms of CLR, CPL, MOV, ANL and ORL |
| Control | SJMP, AJMP, LJMP, JMP @A+DPTR, JZ, JNZ, JC, JNC, JB, JNB, JBC, CJNE, DJNZ, ACALL, LCALL, RET, RETI, NOP |

`JMP label` is an extension that always emits **LJMP**, not a length-dependent optimization. Listings show the resulting LJMP. `JMP @A+DPTR` remains the real computed-jump instruction. `ORL: A,#0F0H` reports a correction instead of silently changing source.

Directives: `ORG`, `EQU`, `DB` (including quoted strings), `DW` (high byte first), `DS` (uninitialized reserved CODE bytes), `END`, labels, semicolon comments, `CSEG [AT address]`, typed symbol aliases (`DATA`, `IDATA`, `XDATA`, `CODE`, `BIT`), `NAME`, `PUBLIC`, `$MOD51`, `$NOMOD51`. Typed aliases define constants; they do not allocate/link independent segments. Unsupported directives are errors.

Numbers: `0F7H`, `247`, `11110111B`, `0xF7`, and single-character constants. Expressions support parentheses, `$` (current address), `+ - * / %`, bitwise operators, `SHL/SHR`, `AND/OR/XOR/NOT`, `HIGH/LOW`, and bit-address notation such as `P1.3` or `20H.7`. Byte operands must resolve to 0–255; 16-bit operands to 0–65535. Use `0FFH` rather than `-1` for a byte immediate.

Assembly uses a symbol/layout pass followed by byte emission, with bounded layout stabilization to resolve chained forward EQU expressions. Errors include missing symbols, invalid operands, overlapping CODE regions, relative branch range errors, 2 KB page violations for AJMP/ACALL, and address overflow. The exported listing includes every source line and the symbol table.

## File formats

| Format | Import | Export |
|---|---|---|
| `.asm`, `.a51`, `.src` | Editable assembly source | Save / Save as |
| `.hex`, `.ihx` | Intel HEX, validated lengths/checksums/EOF/ranges | Intel HEX |
| `.bin` | Raw bytes; prompts for load address | Binary from lowest through highest used address; origin in filename |
| `.lst` | Editable reference text, not executable source | Full source/machine-code listing |
| `.json` | Versioned MDA project | Project with source tabs and CODE image |

Intel HEX record types 00, 01, 02, 03, 04, and 05 are understood. The image must fit the 64 KB CODE address space. Encoded addresses are preserved; start records supply the entry point when present. Without a start record, the lowest loaded address is selected. Binary export fills gaps with the current CODE backing bytes, normally zero.

Compatible **already compiled** Keil/SDCC firmware can run. The app does **not** compile C or link relocatable object files. A real SDCC-produced fixture, source and reproduction instructions are in [fixtures](fixtures/README.md).

## CPU and timing

The independent `CPU8051` class has 128 bytes of internal RAM, a separate SFR array, 64 KB CODE, and 64 KB XDATA. It models all four register banks, bit addressing, the stack, arithmetic flags, parity, port latches and external low-driving inputs. P1–P3 have pull-ups; P0 is open drain with optional external pull-ups. Read-modify-write port operations read the latch; ordinary reads sample resolved pins.

Classic 8051/8031/8751 profiles share this instruction set and RAM. Firmware is loaded into a unified 64 KB CODE view; internal ROM/EPROM capacity and the external EA bus are not electrically modeled. No 8052/Timer 2 profile is offered.

Timers 0/1 support 13-bit, 16-bit, auto-reload, and Timer 0 split modes, gate control, external counter pulses and overflow flags. Timer time comes from executed machine cycles at 11.0592 MHz / 12, not wall-clock intervals. The speed control deliberately slows instruction execution for education; simulated elapsed time is shown separately.

Interrupt support includes INT0, Timer 0, INT1, Timer 1, UART, enable bits, two priority levels, priority nesting, return stacking, edge/level external requests and RETI. Writes to IE/IP and RETI defer another interrupt until a following instruction has executed. Servicing adds two machine cycles. See timing limits below.

UART has separate transmit/receive SBUF behavior, REN, RI/TI, transmission completion, timer-1 baud generation for modes 1/3, and fixed timing for modes 0/2. Receive one character at a time; receive injection is a byte-level test interface.

## Virtual board and tutorials

The board is an original CSS/SVG engineering illustration inspired by the reference workflow, not a verified reproduction of the unavailable PCB scan. It contains a working monitor LCD, keypad, DIP inputs, LEDs and CPU displays. The full board address-region table appears under Watches & address map.

- **AD** selects address entry; enter four hex digits.
- **DA** selects data entry; each pair of hex digits writes a byte at the selected address. Use **+ / −** to move the address.
- Select **CODE**, **IRAM** or **XDATA** explicitly; loading and examining memory are separate from CPU execution.
- **GO** starts at the selected address; **STP** steps the current PC; **RES** resets the trainer.
- **INT** generates an INT0 falling edge and holds it low. Release it using Hardware configuration. **T0** queues a counter input pulse.
- In **Serial monitor** mode the console accepts a documented virtual protocol: `HELP`, `SPACE CODE|IRAM|XDATA`, `AD 2000`, `DA F7`, `READ [address]`, `GO [address]`, `STP`, `STOP`, `RES`, `INT`, `T0`, `+`, `-`, `REGS`. This protocol is not the original MDA ROM protocol.
- Optional **Virtual LCD bus** implements C008H command / C009H data as a teaching API. It is deliberately opt-in and is not represented as the real 8255 PPI wiring. Commands include clear, home and DDRAM addressing for a 16×2 character buffer.

Experiment 01: assemble the example, step three instructions, and observe the actual bytes `74 F7 F5 90 02 80 28`. With monitor initialization selected, the CPU derives A=F7, B=00, PSW=01, SP=50, DPTR=0000. The 8028H hook stops at the virtual monitor; LED 5 uses P1.3 active-low in the provisional wiring.

Experiment 02: assemble and run the editable example and toggle DIPs. The provisional switch bank grounds P1.4–P1.7. Firmware reads pins, swaps the nibbles, ORs F0H, and writes P1. Both latch and resolved pins are visible. LEDs stay off until a loaded program executes a P1 write, then display the output latch by default. DIP changes alone cannot light them. This applies to arbitrary firmware, not just the examples. The tutorial panel contains interactive completion checkboxes for each experiment.

Eighteen editable examples cover the requested categories. Their standalone source files are included under `examples/`; the library loads equivalent source into normal editor tabs. The motor example demonstrates connector output sequencing only and explicitly says that a physical motor model is unavailable.

## Known limits

- **Manual-dependent fidelity is pending.** The two PDFs are needed to verify exact wiring, PPI register functions, PCB placement and monitor keystroke sequences. Wiring is editable and conspicuously provisional.
- ADC, DAC, dot matrix, physical DC/stepper motors, photo-interrupter, speaker, writers and a real 8255 PPI are **not implemented**. Their UI explicitly marks that status; reserved mapped-device accesses fault. The LCD teaching bus is not PPI emulation.
- No original monitor ROM is supplied or fabricated. Only the documented virtual 8028H return hook and a new monitor interface exist. Disable the hook when firmware legitimately uses 8028H. The CPU's arrays stay separate; undocumented physical RAM aliasing between CODE and XDATA is not inferred.
- This is an instruction/machine-cycle educational model, not a silicon or analog circuit simulator. Oscillator-phase interrupt sampling, bus strobes, pull-up transients/current, UART waveforms, framing errors, full 9-bit multiprocessor reception and exact UART mode-2 fractional timing are not modeled. UART input injection is immediate.
- Unimplemented SFR locations are backing storage, not peripheral devices. Do not infer derivative-chip compatibility from writes succeeding there. Upper indirect RAM on these 128-byte targets is absent; writes fault and reads return FFH.
- The assembler supports absolute programs and the documented directive subset, not full Keil macro/INCLUDE/conditional compilation, relocatable segment linking, or SDAS source syntax. Import externally compiled HEX for those workflows.
- The debugger keeps finite history, not reverse execution. Project export is not a RAM/peripheral/timing-state snapshot. Save/Save As use browser downloads rather than overwriting arbitrary local files in place.
- The test suite covers every opcode encoding and broad semantic cases but is not a formal proof of every possible CPU/peripheral state. External compatibility was tested with the included specific SDCC fixture, not every vendor firmware image.
